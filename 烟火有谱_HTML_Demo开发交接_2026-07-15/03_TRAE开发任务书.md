# 烟火有谱｜Trae 阶段一开发任务书

以下内容可直接作为 Trae 的首轮任务说明。

请在现有“烟火有谱”项目中开发一个移动端优先、桌面端可用的完整 HTML Demo。不要继续扩写报名展示页；当前目标是可体验的产品，而不是策划书或静态菜品墙。

## 一、不可改变的产品要求

产品名是“烟火有谱”。绝对主线只有两条：

1. 根据食材选菜谱。
2. 根据菜谱选食材。

用户必须能够完成以下两个闭环：

- 首页 → 选择已有食材 → 查看匹配结果 → 打开菜谱 → 开始图文烹饪。
- 首页/菜谱库 → 选择菜谱 → 查看所需食材 → 生成采购清单 → 勾选完成。

AI、文化内容和小游戏都不得抢走主线，也不要做成单独底部栏目。

## 二、本次只开发阶段一

真实实现：

- 四个底部入口：首页、菜谱、食材篮、我的。
- 90 道菜搜索、筛选、详情和收藏。
- 像素食材搜索、分类、添加、删除。
- 可解释的本地菜谱匹配。
- 菜谱反向生成采购清单，支持合并、勾选和本地保存。
- 图文烹饪步骤、低/中/高三档火力、进度保存。
- 基于明确配料规则的“过敏原、忌口与特殊人群食用提醒”。
- 空状态、无匹配、图片失败、刷新恢复和返回导航。

不要真实实现：

- AI 自然语言解析、照片识别、推荐解释和替换建议。
- 烹饪小游戏逻辑和鼓励评分。
- 登录、云同步、小程序分享和正式小程序发布。

这些未实现功能必须保留可见入口。点击后打开“功能预览”弹层或页面，明确标注“下一阶段接入”，解释未来能力，并提供阶段一替代操作。禁止返回伪造的 AI 识别结果，禁止让用户误以为照片已经上传。

## 三、素材与数据

- 列表图：`assets/dishes/thumbnails/`。
- 详情原图：`assets/dishes/ai/`，仅在进入详情时按需加载。
- 像素食材：`assets/pixel-food/selected/` 和必要时的 `processed-large/`。
- 原始数据：`tools/recipe_data.mjs`。
- 人工核对数据库：`outputs/019f5b8d-091b-74d0-b08b-64333753978d/中西餐菜品数据库_图片已补全.xlsx`。
- 素材授权：保留 `assets/pixel-food/SOURCES.md` 和许可证文件，不改素材文件名。

把原始菜谱数据预处理为前端可直接读取的数据，不要在浏览器内解析 Excel。需要补充演示字段时显式标注为 Demo 补全数据。

## 四、建议工程结构

可以保留 `index.html` 作为新 Demo 入口，将旧报名页归档为 `legacy/registration-demo.html`。推荐结构：

```text
index.html
legacy/registration-demo.html
assets/
data/
  recipes.js
  ingredients.js
src/
  styles/
    tokens.css
    app.css
    responsive.css
  js/
    app.js
    router.js
    state.js
    repositories/
    services/
      matcher.js
      shopping-list.js
      safety-rules.js
      cooking-session.js
      future-services.js
    views/
```

如果为了双击运行而不使用模块系统，可以调整文件结构，但仍要保持数据、业务规则、状态适配和界面渲染的职责分离。不要把全部逻辑继续堆到一个超长 `<script>` 中。

## 五、设计要求

视觉采用“现代东方菜谱册 × 数字灶台”：宣纸米白、烟墨深绿、朱砂红、炉火金。AI 菜品照片负责呈现成品，像素食材负责选择和操作。不要使用紫色渐变、通用 AI 聊天框或千篇一律的卡片仪表盘。

首页首屏只放两个强入口。烹饪页按钮需要足够大，信息层级要能让正在做饭的人一眼看懂。手机端优先，桌面端不要把内容拉成过宽的海报。

## 六、接口要求

使用 `feature-manifest.json` 决定功能是 `enabled` 还是 `preview`。所有阶段二、三能力通过统一服务接口调用，当前接口桩返回 `FEATURE_NOT_AVAILABLE`，界面据此打开预览弹层。不得在各按钮里散落 `alert('暂未开放')`。

任何 API 密钥不得出现在前端。未来真实 AI 接入必须通过服务端或云函数。

## 七、开发顺序

1. 归档报名页并搭建新 Demo 壳层、路由和视觉变量。
2. 转换 90 道菜数据，建立食材别名和基础安全规则。
3. 完成“食材 → 推荐 → 详情 → 图文烹饪”闭环。
4. 完成“菜谱 → 配料 → 采购清单”闭环。
5. 加入收藏、历史、饮食设置和 localStorage 恢复。
6. 加入阶段二、三的功能预览入口和统一接口桩。
7. 按验收清单测试手机、桌面、刷新、空状态和图片失败。

每完成一个步骤先验证，再进入下一个步骤。不要先做小游戏、AI 动画或大段品牌故事。

## 八、交付物

- 可直接打开或按 README 指令启动的 HTML Demo。
- 完整源文件，不只提供截图。
- 数据转换说明和启动说明。
- 阶段一功能状态表。
- 未实现接口的列表，不包含任何真实密钥。
- 完成后的 `05_阶段一验收清单.md` 勾选结果。
