# 烟火有谱｜预留接口与数据契约

## 1. 统一功能状态

所有功能使用以下状态，避免用多个临时布尔值：

- `enabled`：阶段一真实可用，允许调用服务。
- `preview`：入口可见，点击展示功能预览，不调用远程服务。
- `hidden`：当前界面不展示，但代码可以保留。

状态来自 `feature-manifest.json`。视图不得自行假定 AI 或小游戏已经配置。

## 2. 统一服务返回结构

```js
{
  ok: true,
  data: {},
  error: null,
  meta: {
    provider: "local | ai | cloud | platform",
    fallback: false
  }
}
```

失败或未开放：

```js
{
  ok: false,
  data: null,
  error: {
    code: "FEATURE_NOT_AVAILABLE",
    message: "该能力将在下一阶段接入"
  },
  meta: {
    provider: "none",
    fallback: true
  }
}
```

## 3. 阶段一已启用服务

```js
recipeRepository.list(filters)
recipeRepository.getById(recipeId)
recipeRepository.search(query)

pantryStore.list()
pantryStore.add(ingredient)
pantryStore.remove(ingredientId)
pantryStore.clear()

matcher.rank({ recipes, pantry, preferences, safetyRules })
shoppingList.generate({ recipe, pantry, servings })
safetyRules.evaluate({ recipe, preferences })
cookingSession.start({ recipeId })
cookingSession.resume({ recipeId })
cookingSession.advance({ recipeId, stepIndex })
```

`matcher.rank` 的返回项至少包含：

```js
{
  recipeId: "cn-001",
  group: "ready | almost | inspiration",
  coverage: 0.86,
  missingCore: [],
  missingOptional: ["小葱"],
  matched: ["番茄", "鸡蛋"],
  reason: "核心食材齐全，只缺可选的小葱",
  safety: {
    blocked: false,
    warnings: []
  }
}
```

## 4. 阶段二 AI 接口

当前全部为 `preview`，但调用签名固定：

```js
aiServices.parseIngredients({ text, locale })
aiServices.recognizeIngredientPhoto({ file, locale })
aiServices.explainRecommendation({ recipe, pantry, matchResult })
aiServices.suggestSubstitutions({ recipe, missingIngredient, preferences })
```

预期数据：

```js
// parseIngredients
{
  ingredients: [
    { name: "番茄", canonicalId: "tomato", quantity: 2, unit: "个", confidence: 0.98 }
  ],
  needsConfirmation: true
}

// recognizeIngredientPhoto
{
  candidates: [
    { name: "番茄", canonicalId: "tomato", confidence: 0.91 }
  ],
  needsConfirmation: true
}

// suggestSubstitutions
{
  suggestions: [
    {
      ingredientId: "scallion",
      replacementId: "onion",
      type: "flavor | texture | dietary | emergency",
      note: "香气会更甜，和传统做法略有不同"
    }
  ]
}
```

AI 识别结果无论置信度多高，都必须由用户确认后再写入食材篮。AI 只生成解释和候选，不写入过敏原结论。

## 5. 阶段三接口

```js
gameServices.getPreview({ recipeId })
gameServices.start({ recipeId, cookingSteps })
gameServices.submitAction({ sessionId, stepId, action, heat })

authServices.login()
cloudServices.sync({ pantry, favorites, shoppingList, preferences })
shareServices.createRecipeCard({ recipeId })
shareServices.createShoppingListText({ shoppingList })
```

小游戏的 `cookingSteps` 直接复用图文教程数据：

```js
{
  id: "step-03",
  instruction: "倒入番茄翻炒至出汁",
  duration: 120,
  heat: "medium",
  ingredientsUsed: ["tomato"],
  timerRequired: true,
  gameAction: "add_and_stir",
  safetyNote: "注意热油飞溅"
}
```

## 6. 功能预览事件

预览功能点击时统一派发：

```js
openFeaturePreview({
  featureId: "ai.ingredientVision",
  title: "AI 食材识别",
  phase: 2,
  description: "拍下食材，由 AI 给出候选名称并等待确认。",
  limitation: "当前 HTML Demo 未连接识别服务，也不会上传照片。",
  fallbackAction: {
    label: "先手动选择食材",
    route: "#/pantry"
  }
})
```

不要把预览功能处理成浏览器 `alert`。应使用统一底部弹层或预览页，保留完整视觉和替代路径。

## 7. 安全与隐私约束

- 前端接口桩不包含 endpoint、token、secret 或 key。
- 真实 AI 请求只允许进入服务端/云函数代理。
- 阶段一不调用相机和麦克风，也不上传照片。
- 阶段二接入照片识别时，必须在选择照片前说明用途、保存方式和删除方式。
- 安全规则接口与 AI 服务彻底分离。
