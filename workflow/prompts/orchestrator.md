# Orchestrator runbook

Process one recipe per scheduled run. Do not do recipe research or recipe writing yourself when the configured roles are available.

1. Confirm the branch is `codex/recipe-automation`, the repository is consistent, and no unrelated user changes would be overwritten. Pull only when safe.
2. Read `workflow/recipe-progress.json` first and then the newest `workflow/runs/*.json`. Resume an unfinished run; otherwise select the next pending recipe.
3. Persist `in_progress` plus a new run log before research. Create an edit-before snapshot with `npm run rag:snapshot -- --output <path>`.
4. Invoke Researcher and persist the evidence package. Every new or changed qualifying source is normalized and ingested independently before selection; unchanged documents reuse their existing content hashes and embeddings. If exactly one qualifying source remains, use it directly when it matches the target, is complete and internally coherent, and has no reliable historical-source conflict. Require `sourceMode: "single_source"` plus `singleSourceReason`. If two or more qualifying sources remain, require Researcher to preserve each complete source separately and Editor to select exactly one whole recipe. The selection order is: source completeness/internal coherence first, then usable source images and step-image coverage, then richer executable steps, then richer ingredient coverage. Do not merge variants or supplement the winner from another source.
   For source images, persist original image URLs plus the repository destination mapping. The orchestrator, not Editor, downloads the selected source's authorized images into `assets/dishes/sources/<recipe-id>-<slug>/`, verifies HTTP type, local file existence, size and SHA-256, and supplies those local paths to Editor. Runtime recipe data must load local repository assets only; original URLs remain provenance metadata and must never be used as runtime image paths. A selected source needs a finished-dish image and at least one step image. Missing photos for some otherwise complete textual steps do not invalidate a single source and must not be filled from another source.
5. Invoke Editor with that exact package and the target record. Run `npm run rag:validate -- --target <id> --before <snapshot> --full`. Add `--allow-source-change` only when the evidence proves that the old source is stale or mismatched and the replacement is the selected primary source. Return concrete errors to Editor, at most two redo attempts.
6. Invoke Reviewer with the identical evidence package, the edited target, and validator JSON. Return concrete issues to Editor, at most two redo attempts; rerun the validator after every edit.
7. After Reviewer PASS, run `npm run test:workflow:deterministic`. This command intentionally excludes `npm run test:ai`.
8. Update the run log throughout. Commit only the intended run artifacts and push only to `codex/recipe-automation`.
9. Mark the recipe `done` only after Reviewer PASS, deterministic tests, commit, and push all succeed. Record the commit SHA. On a recipe-level unrecoverable failure, persist `failed`, leave that recipe unpublished, and continue to the next requested recipe. Stop the batch only when repository integrity, shared infrastructure, commit, or push failure prevents safe continuation.
